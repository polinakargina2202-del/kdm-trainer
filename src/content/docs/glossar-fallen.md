# Glossar & typische IHK-Fallen

## Prüfungsoperatoren

| Operator | Was du tun sollst |
|---|---|
| **nennen / angeben** | kurze fachlich richtige Stichpunkte; keine lange Erklärung nötig |
| **beschreiben** | Sachverhalt mit wesentlichen Merkmalen in eigenen Worten darstellen |
| **erläutern** | erklären **und** Zusammenhang/Folge verdeutlichen, möglichst mit Szenariobezug |
| **begründen** | Entscheidung + fachliches Argument, warum sie passt |
| **vergleichen** | gemeinsame Kriterien verwenden und Unterschiede/Gemeinsamkeiten gegenüberstellen |
| **beurteilen** | Kriterien anwenden, abwägen und zu einem begründeten Urteil kommen |
| **berechnen / ermitteln** | nachvollziehbarer Rechenweg + Ergebnis + Einheit |

> **IHK-Regel:** Wird eine feste Anzahl verlangt, z. B. „Nennen Sie vier Kriterien“, liefere vier klare, unterschiedliche Kriterien.

## Begriffe A–Z

**Abnahme:** Bestätigung, dass ein Werk im Wesentlichen vertragsgemäß hergestellt wurde; hat wichtige Rechtsfolgen beim Werkvertrag.

**API:** definierte Schnittstelle, über die Systeme Funktionen oder Daten automatisiert austauschen.

**Aufwand / Ertrag:** Begriffe der Finanzbuchhaltung. Nicht jeder Aufwand ist Kosten; nicht jeder Ertrag ist Leistung.

**Backup:** zusätzliche Sicherungskopie zur Wiederherstellung. Nicht mit RAID verwechseln.

**BPMN:** Notation für Geschäftsprozesse mit Events, Tasks, Gateways sowie Pools/Lanes.

**Break-even:** Punkt, an dem Erlöse und Gesamtkosten gleich sind; im DB-Modell `Fixkosten / DB je Einheit`.

**Change:** geplante Änderung an einem Service/System.

**Deckungsbeitrag:** Erlös abzüglich variabler Kosten; Beitrag zur Deckung von Fixkosten und Gewinn.

**Datenhoheit:** Frage, wer über Daten verfügen, sie herausgeben oder nutzen darf; nicht identisch mit Datenschutz.

**Digitalisierungsgrad:** Maß dafür, wie weit Daten/Prozessschritte digital unterstützt, verbunden oder automatisiert sind.

**DSFA:** Datenschutz-Folgenabschätzung bei Verarbeitungen, die voraussichtlich ein hohes Risiko für Rechte und Freiheiten natürlicher Personen verursachen.

**ETL:** Extract → Transform → Load; Daten extrahieren, aufbereiten/transformieren und in ein Zielsystem laden.

**Fremdschlüssel:** Attribut, das auf einen Schlüssel einer anderen Tabelle verweist.

**Incident:** ungeplante Störung oder Qualitätsminderung eines IT-Service; Ziel ist schnelle Wiederherstellung.

**Kostenträger:** Wofür sind Kosten entstanden? z. B. Produkt, Projekt oder Auftrag.

**Kostenstelle:** Wo sind Kosten entstanden? z. B. Verwaltung oder IT.

**Lastenheft:** Auftraggeber beschreibt **was** benötigt wird.

**Pflichtenheft:** Auftragnehmer beschreibt **wie** Anforderungen umgesetzt werden.

**Pseudonymisierung:** Zuordnung zur Person ist mit Zusatzinformation noch möglich; Daten bleiben grundsätzlich personenbezogen.

**Referentielle Integrität:** Fremdschlüssel dürfen nicht auf nicht vorhandene Datensätze verweisen.

**Service Request:** standardisierte Anforderung, keine Störung, z. B. Passwort-Reset oder Berechtigungsantrag.

**SLA:** messbare Vereinbarung zur Servicequalität, z. B. Verfügbarkeit/Reaktions-/Wiederherstellungszeit.

**TCO:** Total Cost of Ownership; betrachtet nicht nur Anschaffung, sondern auch Betrieb, Lizenzen, Wartung, Support, Energie, Migration usw.

**TOM:** technische und organisatorische Maßnahmen zum Schutz personenbezogener Daten.

**UX / UI:** UI = sichtbare Oberfläche; UX = gesamte Nutzungserfahrung.

## Die häufigsten Fallen

| Falle | Richtig denken |
|---|---|
| **RAID = Backup** | Falsch. RAID kann Ausfälle einzelner Datenträger abfangen; Backup schützt zusätzlich gegen Löschen, Ransomware, Brand usw. |
| **Umsatz = Gewinn** | Falsch. Vom Umsatz gehen Kosten ab. |
| **Preis = Deckungsbeitrag** | Nur wenn keine variablen Kosten vorhanden sind. Sonst `Preis − variable Kosten`. |
| **Besitz = Eigentum** | Besitz = tatsächliche Sachherrschaft; Eigentum = rechtliche Herrschaft. |
| **Rabatt = Skonto** | Rabatt mindert Preis unabhängig vom Zahlungszeitpunkt; Skonto hängt an schneller Zahlung. |
| **Handelsspanne = Kalkulationszuschlag** | Unterschiedliche Nenner: Verkaufspreis vs. Einstandspreis. |
| **Pseudonymisiert = anonym** | Falsch. Pseudonymisierte Daten können mit Zusatzwissen wieder zugeordnet werden. |
| **Einwilligung immer nötig** | Falsch. DSGVO kennt mehrere mögliche Rechtsgrundlagen. |
| **INNER JOIN = LEFT JOIN** | INNER nur passende Datensätze; LEFT zusätzlich alle Datensätze der linken Tabelle. |
| **WHERE = HAVING** | WHERE filtert Zeilen vor Gruppierung; HAVING filtert Gruppen/Aggregate. |
| **Korrelation = Ursache** | Falsch. Statistischer Zusammenhang beweist keine Kausalität. |
| **Werkvertrag = Dienstvertrag** | Werkvertrag schuldet Erfolg; Dienstvertrag grundsätzlich Tätigkeit. |
| **Leasing immer außerbilanziell** | Zu pauschal. Bilanzierung hängt von Vertragsgestaltung und wirtschaftlicher Zurechnung ab. |
| **Skonto lohnt sich immer** | Zu pauschal. Kosten des Skontoverzichts mit alternativer Finanzierung und Liquidität vergleichen. |
| **„digital“ = automatisch besser** | Wirtschaftlichkeit, Sicherheit, Datenschutz, Usability und Organisation mitbewerten. |

## Antwortmuster für offene Aufgaben

**„Erläutern Sie einen Vorteil …“**  
`Vorteil nennen → erklären, wodurch er entsteht → Bezug zum Fall herstellen.`

**„Begründen Sie Ihre Auswahl …“**  
`Variante wählen → entscheidendes Kriterium nennen → erklären, warum dieses Kriterium im Szenario erfüllt ist.`

**„Beurteilen Sie …“**  
`Kriterien festlegen → Pro/Contra bzw. Ist/Soll vergleichen → begründetes Gesamturteil.`

**„Nennen Sie Ursache, Risiko und Gegenmaßnahme …“**  
Achte darauf, die drei Ebenen nicht zu vermischen: Ursache = Auslöser; Risiko = mögliches Ereignis; Auswirkung = Folge; Gegenmaßnahme = Reaktion/Vorbeugung.
